# DEMO_CHECKLIST.md — 人に使ってもらう日の手順

Club Activities（反対立論）の最小授業を、別の PC で人に触ってもらうためのメモ。

---

## 前日までに（ここが本番）

- [ ] その PC で `npm run doctor` が**すべて緑**になる
- [ ] **自分で一度、最後まで音声を通しておく**

2つ目が肝心。**この授業は実接続でしか確かめられない部分がある。**
当日その場で初めて試すと、転んだときに直す時間が無い。

一度通すときに見るのはこの3点。

1. AI が `against` の質問を**1問だけ**して**止まる**か（答えを先に言ってしまわないか）
2. こちらが黙っている間、**AI が待てる**か（間を置くと割り込んでこないか）
3. 「反対」と答えたあと、**`optional` の質問へ進む**か

3 が動かない場合、モデルが `mark_phase_complete` を呼べていない可能性が高い。
そのときは `npm run dev` のログに `[phase]` の行が出ているかを見て、
私に伝えてもらえれば instructions か tool の説明文を調整する。

---

## 当日の流れ

```bash
npm run doctor     # 念のため
npm run dev
```

1. ブラウザで `http://localhost:3000/student` を開く
2. 「AI授業を開始」
3. 授業画面の「開始」を押す
4. **マイクの利用を許可する**（ここで止まる人が多い）
5. AI が日本語で話しかけてくる。声で答える

---

## 相手に先に伝えておくこと

- **いまの授業は3問だけ。2〜3分で終わる**（`against` → `optional` → `make A B`）
- 答えは**日本語でよい**
- **点数は出ない**（採点は音声セッション中に行わない設計のため）
- **音声は保存しない。書き起こしは保存する**

---

## 転んだときの一次対応

| 症状 | 見るところ |
|---|---|
| 画面は出るが AI が話さない | マイク権限。ブラウザのアドレスバーの左側 |
| 「開始」でエラー | `npm run doctor`。キーとモデル名が有効か |
| AI が答えを先に言う | instructions のルールが効いていない。ログを控えて共有 |
| `optional` へ進まない | `mark_phase_complete` が呼ばれていない。同上 |
| 途中で切れた | もう一度「開始」。フェーズは DB に保存されているので続きから戻る |

`npm run dev` を動かしているターミナルのログが一番の手がかり。
**エラーが出たらその行を残しておいてもらえると、原因を特定しやすい。**
