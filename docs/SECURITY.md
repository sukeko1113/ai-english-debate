# SECURITY.md — セキュリティと個人情報

未成年の音声・発話・成績を扱うシステムであることを前提に読むこと。

---

## 1. OpenAI APIキー

### 契約主体

| 段階 | 契約主体 | 備考 |
|---|---|---|
| 開発・検証 | 開発者個人の OpenAI Platform アカウント | 生徒は OpenAI と何の関係も持たない |
| 学校運用 | **学校名義のアカウントへ移行を検討** | 費用・契約・データ管理の責任が学校側になる |

**生徒は ChatGPT アカウントも OpenAI アカウントも不要。**
API キーは1本で全生徒分をまかなう。

### 置き場所

- サーバーの環境変数 `OPENAI_API_KEY` のみ
- `lib/openai/client.ts` からのみ読む。他ファイルで `process.env.OPENAI_API_KEY` を参照しない
- `NEXT_PUBLIC_*` に絶対に入れない
- ログ・エラーメッセージ・スタックトレースに含めない
- `.env` は `.gitignore`。`.env.example` には変数名のみ

### Claude Code のクラウド環境に置かない

クラウド環境の環境変数は、その環境を使う人が誰でも読める。専用のシークレットストアはない。
**`OPENAI_API_KEY` をクラウド環境の環境変数に設定しない。**

開発中に実際の音声接続をテストする必要があるときは、ローカルで行う。
クラウドセッションでは接続部分をモックする。

### 使用量上限

OpenAI Platform で月額のハードリミットを必ず設定する。
バグによる無限ループ、レート制限の抜け漏れに対する最後の防御線。

## 2. 信頼境界

**ブラウザを通った値はすべて改ざん可能。**

WebRTC 構成では function call がブラウザのデータチャネルに届く。生徒は開発者ツールで
引数を書き換え、呼ばれていない tool を呼び、API を直接叩ける。

### 具体的なルール

| 項目 | ルール |
|---|---|
| `student_id` | リクエストから受け取らない。認証セッションから引く |
| `session_id` | 受け取るが、必ず所有者を検証する |
| `item_id` / `question_id` | DB に存在し、かつそのセッションの教材に属することを検証 |
| 点数 | **受け取らない。** 点数を引数に持つ API と tool を作らない |
| 教材の正解 | ブラウザに送らない。`GET /api/lessons/today` から `answer` を除外する |

他人のリソースへのアクセスは `403` ではなく `404` を返す。存在自体を漏らさないため。

## 3. 認証と権限

### 認証

- 学校アカウント（Google Workspace / Microsoft Entra ID）との OAuth を想定
- ただしドメイン外の利用者も想定するため、メール + パスワードも用意する
- **誰でもサインアップできる状態にしない。** 教員が発行するクラス招待コードを必須にする

### 権限

| ロール | できること |
|---|---|
| 生徒 | 自分のセッション・答案・採点結果の閲覧。自分のセッションへの記録 |
| 教師 | 担当クラスの生徒のデータ閲覧。採点の修正。教材の編集 |
| 管理者 | 全体。再採点の実行 |

### 二重防御

Supabase の RLS を設定する。**ただし RLS だけに依存しない。**
API 層でも必ず所有者・権限を検証する。RLS はバイパスされうる経路（service role キーの誤用など）
があるため、単独の防御線にしない。

`scores` テーブルへの INSERT は service role のみ。生徒・教師のロールから書き込めないこと。

## 4. 未成年データ

### 保存するもの / しないもの

| データ | 扱い |
|---|---|
| 音声そのもの | **保存しない。** WebRTC のストリームはディスクに落とさない |
| 書き起こし | 保存する。保持期間を設定する（初期案：学年度末 + 1年） |
| 答案 | 保存する |
| 採点結果 | 保存する |
| 氏名 | 表示名のみ。学籍番号との紐付けは別テーブルに分離 |

音声を保存しない理由：発音採点は MVP で行わず、保存する必要性がない。
必要性のないデータを持たないのが最も確実な保護になる。

### Safety Identifier

OpenAI へ送る識別子に **生の学籍番号や氏名を使わない。**

```
safetyId = sha256(student_id + SAFETY_ID_SALT)
```

`SAFETY_ID_SALT` は環境変数。`lib/openai/safety-id.ts` に集約する。

### 学校運用前に確認すること

コードの問題ではないが、実装と同時に進める必要がある。

- [ ] 学校または教育委員会の情報セキュリティポリシーで、外部 SaaS（OpenAI / Supabase / Vercel）の
      利用が認められるか。認められる場合の申請手順
- [ ] OpenAI の Under 18 に関するガイダンスを確認し、学校運用ポリシーを策定
- [ ] 保護者への説明と同意の取得方法
- [ ] データの保持期間と削除手順
- [ ] Supabase のリージョンを東京（ap-northeast-1）にする。**後から変更できない**

## 5. 監査

以下の操作は `audit_logs` に記録する。

| 操作 | 記録内容 |
|---|---|
| 採点の修正 | 教師 ID、対象、変更前、変更後、理由 |
| 教材の変更 | 編集者、教材 ID、バージョン |
| AI生成教材の承認 | 承認者、内容 |
| 再採点の実行 | 実行者、対象セッション、新旧ルーブリック |
| 権限の変更 | 実行者、対象、変更内容 |

`audit_logs` は追記のみ。UPDATE / DELETE を許可しない。

---

## 6. レート制限

`/api/realtime/session` は課金に直結する。認証済みでも無制限にしない。

- 生徒あたり 1時間に N セッションまで
- 同時アクティブセッションは1生徒につき1つ
- 異常値を検出したらログに残し、必要なら一時停止

---

## 7. リポジトリに入れないもの

- `.env`、API キー、Supabase の service role キー
- 実在する生徒の氏名・音声・成績・書き起こし
- 教材の「答え」を含むファイルのうち、公開リポジトリに置けないもの

テストデータは架空のものを使う。`content/` の教材は教材そのものなので問題ない。

## 8. 依存関係

- 新しい npm パッケージを追加するときは、PR 本文に理由を書く
- 音声・認証・DB に関わるパッケージは特に慎重に選ぶ
- `npm audit` を CI に入れる
